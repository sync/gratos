# How Gratos differs from Grats

The rest of these docs is upstream Grats' (v0.0.36), vendored byte for byte: it says `grats`
where Gratos says `gratos`, and it documents CLI features Gratos does not have. It is not edited,
so this page is the correction. Read it before following a vendored page. (The grats skill points
at `node_modules/grats/llm-docs/…`; in this repo those docs are `packages/gratos/llm-docs/`.)

Gratos' own pages are this one, [effect.md](./effect.md) (Effect resolvers and the server's Effect
layer) and [server.md](./server.md) (the server core: `createServer`, its hooks, the HTTP matrix
and the shipped plugins). Code blocks tagged `file=` are compared with that file by
`examples/orders/test/docs.test.ts`.

## Renamed

- **The package is `@dblechoc/gratos`**, not `grats`. Depend on it under that name (in this
  workspace, `"@dblechoc/gratos": "workspace:*"`); models import Grats' types (`Int`, `Float`,
  `ID`, `GqlInfo`, `GqlScalar`) from it:

  ```ts file=examples/orders/src/models/Order.ts
  import type { Float, ID, Int } from "@dblechoc/gratos";
  ```

- **The binary is `gratos`**, not `grats`: `npx grats`, `npm run grats` and
  `node_modules/grats/dist/src/cli.js` become `gratos` (in a package script, say) and
  `node_modules/@dblechoc/gratos/src/cli.ts`. Node runs it from source, with no build step.

  ```json file=packages/gratos/package.json
    "bin": {
      "gratos": "./src/cli.ts"
    },
  ```

- **`libraryImport` is a new config option**, under the same `grats` key of `tsconfig.json`. It is
  the module the generated `schema.ts` imports `GqlScalar` from, and the one error messages tell
  you to import `Int`, `Float` and `GqlInfo` from. Its default is `@dblechoc/gratos` (Grats always
  says `grats`):

  ```json file=packages/gratos/src/upstream/configSpecRaw.json
      "libraryImport": {
        "description": "The module specifier of the library that exports Grats' types (`Int`, `Float`, `ID`, `GqlInfo`, `GqlScalar`). The generated TypeScript schema imports `GqlScalar` from it, and error messages tell you to import `Int`, `Float` and `GqlInfo` from it.",
        "type": { "kind": "string" },
        "nullable": false,
        "default": "@dblechoc/gratos"
      }
  ```

- **The default headers of the generated files name Gratos**: "generated by Gratos (based on
  Grats, …)" and "Regenerate by running `gratos`." (Grats says `npx grats`).

The config key stays `grats`, and so does the directive namespace Grats writes in a field's
`extensions` (`extensions.grats.directives`). Gratos' own markers live beside it, in
`extensions.gratos` (see [effect.md](./effect.md)).

## The `gratos` CLI

Grats' CLI, flag by flag. `cli.test.ts` (in `packages/gratos/test/`) runs the real binary on each
row: a removed one exits 1 and writes nothing; a kept one runs.

| Grats        | In Gratos                                                                        |
| ------------ | -------------------------------------------------------------------------------- |
| `--watch`    | Removed. Use `node --watch-path` (below)                                         |
| `--fix`      | Removed, with the code actions behind it. Fix the diagnostic by hand             |
| `locate`     | Removed. There is no command to find where a type or field is defined            |
| `--tsconfig` | Kept. Without it, the nearest `tsconfig.json` from the current directory         |
| `--version`  | Kept, also as `-V` (Grats) and `-v`                                              |
| `--check`    | New. Writes nothing, and exits 1 when a generated file is missing or out of date |

`gratos` alone writes the generated files that are out of date, and leaves the others untouched.
The scripts a package runs:

```json file=examples/orders/package.json
    "codegen": "gratos --tsconfig src/tsconfig.json",
    "codegen:check": "gratos --check --tsconfig src/tsconfig.json",
```

`--help` (`-h`) prints effect/cli's help, which also lists its built-in flags (`--wizard`,
`--completions`, `--log-level`).

## Removed

None of these ports to the TypeScript 7 API, so all of them were cut (M1b in `docs/plan.html`):

- **Watch mode** (`--watch`). The dev loop restarts the app with `node --watch-path` instead, and
  the lazy `@dblechoc/gratos/dev` step regenerates the schema when it boots (see "The dev loop"
  in [effect.md](./effect.md)):

  ```json file=examples/orders/package.json
      "dev": "GRATS_DEV=1 node --watch-path=src/models --watch-path=src/services --watch-preserve-output src/server.ts",
  ```

- **`--fix`** and the code actions it applied (a docblock tag's casing, a deprecated tag).
- **`locate`** (`grats locate User.name`).
- **The editor plugin**: Grats' experimental TypeScript language-service plugin (`initTsPlugin`),
  which showed Grats' diagnostics and code actions in the editor. Run `gratos` (or
  `gratos --check`) to see them.

## Added

- **Effect return types.** Gratos reads `Effect.Effect<A, E, R>` as `A` and
  `Stream.Stream<A, E, R>` as a subscription's items. Only the qualified names count: a bare
  `Effect<A>` gets an error that suggests `Effect.Effect<A>`, and a renamed import
  (`import { Effect as Fx }` with `Fx.Effect<A>`, or `import * as Fx from "effect/Effect"`) gets
  one that suggests importing `Effect` under its own name. The rules are in
  [effect.md](./effect.md), "Return types". With `EXPERIMENTAL__emitResolverMap` on, an Effect
  field or a Stream subscription is an error.
- **Generated resolvers.** Every method field gets its own explicit `resolve` (Grats uses the
  default resolver for some), with its arguments passed positionally.
- **Outputs never overwrite each other.** `gratos` fails, writing nothing, when two of its outputs
  (the schema, `schema.ts`, the enums module) are one file, also through a symbolic or hard link.
- **A server and an Effect layer**: `@dblechoc/gratos-server` ([server.md](./server.md)) and
  `@dblechoc/gratos-server/effect` ([effect.md](./effect.md)). Grats leaves the server to you; the
  vendored pages that use `graphql-yoga` still work with the generated schema, but Effect
  resolvers need `effectSchema`.
